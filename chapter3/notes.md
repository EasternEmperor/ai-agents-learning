# 三、用户记忆与知识库

## 3.1 用户记忆系统
记忆能力的评估：三层次框架
第一层：基础回忆
第二层：多会话检索
第三层：主动服务

轨迹(Trajectory)是一次 Agent 运行过程的完整历史记录（上下文）：时间顺序
用户长期记忆是跨会话、跨实例的持久化存储：键值对形式
业务状态、任务阶段：高层状态抽象

四种存储格式：
1. Simple Notes：极简主义，每条记忆是最小的、不可再分的事实，**开销低**，但事实之间的**关联性丢失**
2. Enhanced Notes：完整上下文的段落，**语义完整**，**存储冗余，更新复杂**
3. JSON Cards：三层嵌套结构（类别->子类别->键值对），**支持部分更新**，刚性分类**丢失多维性**
4. Advanced JSON Cards：不仅记录事实，还加入信息来源的叙事背景（backstory）、主体身份（person）、与用户的关系（relationship）和时间戳，**生成维护成本高**

进阶知识：可执行代码
将聚合、冲突检测、约束执行交给代码，将规则写成普通函数

用户记忆的认知科学基础
- 情景记忆：具体事件时间、对象和细节
- 语义记忆：具体事件抽象出的一般性知识
- 程序记忆：行为模式和流程的记忆

记忆框架案例：开源项目
Mem0：v2写入时消除歧义(update, add, drop, noop)，有不可逆的丢失历史信息的风险；v3仅追加，混合检索(only add)，加入时间信息
Memobase：用户画像与事件记忆

记忆压缩与整理机制
1. 重要性评分：考虑访问频率、时间衰减、情感强度、信息独特性等加权评分
2. 聚类：相似记忆分组，每组产生摘要
3. 抽象与泛化：提取一般性规律转化为语义或程序记忆

## 3.2 RAG基础：构建 Agent 的知识获取管道
文档分块(Chunking)：
原因：1. 嵌入模型对输入长度有限制，且一整篇文档只压缩成一个向量，多个主题混在一起，语义混乱难以精确召回；2. 检索的目标是只把相关的那部分注入上下文
缺点：无论采用哪种策略，分块都会切断片段与其原始上下文的练习。
分块策略：
1. 固定大小分块
2. 递归/结构感知切分：按文档的自然边界（章节、段落、句子）递归切分
3. 于一切分


“稠密”向量的每个维度都有数值，“稀疏”向量大部分维度为零

稠密嵌入：从词汇关联到语义理解
1. 从Word2Vec到上下文感知：每个词固定向量 -> 上下文感知(self-attention)向量

稀疏嵌入：精确匹配的关键词检索
TF-IDF（词频-逆文档频率）：一个词在当前文档中出现得越多、在整个语料库中越少见，它对检索越重要
BM25：仍然是“词越稀有，权重越高”，但是度量方式变了：分子从“文档总数 𝑁”换成“不含该词的文档数𝑁−DF(𝑡)”

混合检索：两全其美的艺术
稠密检索懂语义但可能漏掉关键词；稀疏检索精确匹配但读不懂同义词。混合检索即：两个引擎都跑，结果合并
1. 第一阶段：并行检索
2. 第二阶段：结果融合。难点在于两路得分不可直接比较，常用的融合方法是倒数排名融合(RRF)，完全抛开原始得分、只看排名
3. 第三阶段：神经重排序。在结果融合产生的候选池中进行打分精排
