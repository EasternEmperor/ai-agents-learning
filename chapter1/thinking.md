1. 如果你要设计一个专门处理航班订票的客服系统，你会选择工作流模式还是自主Agent模式？有没有可能在同一个系统中混合使用两种模式？
工作流作为主干，自主 Agent 处理开放式需求。两种模式可以用在同一个系统里，甚至可以在同一次对话中交接。
   环节	                采用模式	    原因
   理解需求、追问、比较航班	自主 Agent	乘客可能说“周五下班后出发，别太晚到，贵一点也行”。Agent 可以理解这些偏好，决定先问什么、查什么，并解释取舍。
   核价、确认、支付、出票	工作流	    每一步都有明确的前置条件。比如价格变了就重新确认，支付结果不明就先查订单状态，避免重复扣款。

例如，乘客说：“周五晚上从上海去成都，尽量直飞。”Agent 先确认日期和可接受的起飞时间，再查航班、给出候选。乘客选中一班后，系统进入订票工作流：重新核价和验库存 → 展示总价与退改条件 → 用户确认 → 支付 → 出票。如果航班售罄，工作流把原因交回 Agent，由它继续找备选；选定新航班后，再进入确认流程。

2. 护栏部分提到了工具风险评级。如果一个工具在大多数情况下是低风险的，但在特定参数组合下变为高风险（如delete_file 删除普通文件 vs 删除系统文件），你会如何设计动态风险评估
给工具设一个基准风险，再对每一次具体调用重新评级。`delete_file` 可以有默认等级，但最终决定取决于它实际会删什么、影响多大、能不能恢复。评估应由工具执行层强制完成，不能由 Agent 自己决定是否放行。
